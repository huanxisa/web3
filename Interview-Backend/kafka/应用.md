# kafak应用的面试题


### 基础概念类

**1. Kafka 核心概念解释**
```
Producer：消息生产者，负责发布消息到 Kafka broker
Consumer：消息消费者，从 broker 读取消息
Broker：Kafka 服务器，负责消息存储
Topic：消息主题，相当于消息的分类
Partition：分区，每个 topic 可以有多个分区，提供并行处理能力
```

**2. 消费者组（Consumer Group）**
```
- 定义：同一个消费组中的消费者共同消费某个主题的消息
- 特点：
  1. 一个分区只能被同一消费组中的一个消费者消费
  2. 消费组实现了消息的广播和单播
  3. 提供了水平扩展和故障转移能力
```

### 生产者相关

**1. Producer 发送消息流程**
```
1. 序列化消息
2. 根据分区策略选择目标分区
3. 消息缓存到批次（batch）
4. 发送到服务器
具体步骤：
- ProducerRecord 创建
- 序列化
- 分区器分区
- 累加到 RecordAccumulator
- Sender 线程发送
```

**2. 三种发送方式对比**
```
1. 发送并忘记（fire-and-forget）
   - 不关心消息是否到达
   - 可能丢失消息
   - 性能最好

2. 同步发送
   send().get()
   - 等待消息发送完成
   - 可靠性高
   - 性能较差

3. 异步发送
   send(callback)
   - 不阻塞，通过回调处理结果
   - 性能好
   - 可以处理发送结果
```

### 消费者相关

**1. 消费方式**
```
1. 自动提交 offset
   enable.auto.commit = true
   - 优点：简单
   - 缺点：可能重复消费或丢失消息

2. 手动提交 offset
   - 同步提交：commitSync()
   - 异步提交：commitAsync()
   - 优点：可控性强
   - 缺点：需要自己处理提交逻辑
```

**2. 重平衡（Rebalance）机制**
```
触发条件：
1. 消费组成员数量发生变化
2. 订阅主题数量发生变化
3. 主题分区数量发生变化

过程：
1. 暂停所有消费者消费
2. 重新分配分区
3. 恢复消费
```

### 性能调优

**1. 生产者性能优化**
```
1. batch.size 调大（例如：16KB -> 32KB）
2. linger.ms 适当增加（例如：0 -> 10ms）
3. compression.type 启用压缩（如 snappy）
4. buffer.memory 根据内存调整
5. acks 根据可靠性要求选择
```

**2. 消费者性能优化**
```
1. fetch.min.bytes 调大
2. fetch.max.wait.ms 适当设置
3. max.poll.records 调整
4. 增加消费者数量
5. 使用多线程消费
```

### 高级特性

**1. 消息顺序性保证**
```
1. 单分区顺序：
   - 消息发送到同一分区
   - max.in.flight.requests.per.connection=1

2. 多分区顺序：
   - 业务上保证关联消息发送到同一分区
   - 使用消息键（key）
```

**2. 零拷贝技术**
```
传统方式：
磁盘 -> 内核空间 -> 用户空间 -> socket缓冲区 -> 网卡

零拷贝：
磁盘 -> 内核空间 -> 网卡
使用 sendfile() 系统调用，减少数据拷贝次数
```

### 实战问题

**1. 如何处理消息积压**
```
解决方案：
1. 短期：
   - 增加消费者数量
   - 增加分区数
   - 优化消费者性能

2. 长期：
   - 分析积压原因
   - 优化生产消费速率
   - 考虑流量削峰
```

**2. 消息可靠性保证**
```
生产者端：
1. acks=all
2. retries > 0
3. 使用回调确认

消费者端：
1. 手动提交 offset
2. 幂等性处理
3. 本地事务

Broker 端：
1. replication.factor > 1
2. min.insync.replicas > 1
```

### 架构设计

**1. 高可用部署方案**
```
1. Broker 集群：
   - 至少 3 个 broker
   - 跨机架部署
   - 配置 rack awareness

2. ZooKeeper 集群：
   - 奇数节点（如 3、5 个）
   - 独立部署
   - 监控和备份

3. 副本配置：
   - replication.factor >= 3
   - min.insync.replicas >= 2
