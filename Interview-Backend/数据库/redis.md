# Redis高级面试题及答案

## 1. 数据结构与底层实现

**Q: Redis的字符串底层实现原理是什么？为什么要设计简单动态字符串(SDS)而不是直接使用C的字符串？**

A: Redis设计SDS的主要原因：
- 获取字符串长度的时间复杂度为O(1)，因为SDS结构中保存了len属性
- 避免缓冲区溢出，SDS会自动扩容
- 减少内存重分配次数，通过空间预分配和惰性空间释放
- 二进制安全，可以存储任意二进制数据
- 兼容部分C字符串函数

## 2. 持久化机制

**Q: 在进行Redis数据同步时，AOF重写过程中如何保证数据一致性？**

A:
1. Redis执行fork()创建子进程
2. 子进程创建新的AOF文件，遍历数据库中的键值对，写入命令
3. 父进程继续处理请求，将新的写命令追加到AOF缓冲区和AOF重写缓冲区
4. 子进程完成重写后，父进程将AOF重写缓冲区中的内容追加到新AOF文件
5. 原子性地替换旧的AOF文件

## 3. 主从复制

**Q: Redis主从复制的完整流程是怎样的？在数据同步工具开发中需要注意哪些问题？**

A:
1. 建立连接阶段：
   - 从节点发送PSYNC命令
   - 首次复制使用全量同步
   - 断线重连使用部分重同步
   
2. 数据同步阶段：
   - 主节点执行BGSAVE生成RDB文件
   - 主节点将RDB文件发送给从节点
   - 从节点清空旧数据，载入RDB文件
   
3. 命令传播阶段：
   - 主节点将写命令发送给从节点
   - 从节点执行命令保持数据一致性

注意事项：
- 网络延迟和带宽限制
- 大量数据同步时的内存压力
- 避免主从切换时的数据丢失

## 4. 集群方案

**Q: Redis Cluster的槽位分配机制是怎样的？在设计数据同步工具时如何处理集群扩缩容场景？**

A:
- Redis Cluster使用16384个槽位
- 使用CRC16算法计算key的槽位
- 槽位重分配过程：
  1. 准备阶段：确定要迁移的槽位
  2. 迁移阶段：逐个键值对迁移
  3. 完成阶段：更新集群状态

数据同步工具需要：
- 监控集群拓扑变化
- 处理槽位迁移过程中的请求转发
- 保证迁移过程中的数据一致性

## 5. 内存管理

**Q: Redis的内存淘汰策略有哪些？如何选择合适的淘汰策略来优化数据同步性能？**

A:
1. volatile-lru：从设置了过期时间的键中移除最近最少使用的键
2. allkeys-lru：从所有键中移除最近最少使用的键
3. volatile-random：随机移除设置了过期时间的键
4. allkeys-random：随机移除任意键
5. volatile-ttl：移除即将过期的键
6. noeviction：不淘汰，返回错误

选择建议：
- 数据同步场景建议使用allkeys-lru
- 需要保证数据完整性时使用noeviction
- 有明确过期时间的场景可以使用volatile-ttl

## 6. 事务与原子性

**Q: Redis的事务实现原理是什么？在数据同步工具中如何保证原子性和一致性？**

A:
- Redis事务通过MULTI、EXEC、WATCH等命令实现
- 事务中的命令入队后会被顺序执行
- Redis不支持回滚，只会记录错误
- WATCH命令实现乐观锁，防止竞态条件

数据同步工具建议：
- 使用Lua脚本保证复杂操作的原子性
- 实现自定义的事务重试机制
- 记录事务执行状态，支持断点续传
