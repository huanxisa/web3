### MySQL 面试题

#### 1. 存储引擎相关
**Q: InnoDB 和 MyISAM 的区别，以及在数据同步场景下需要特别注意什么？**

A: 主要区别：
- InnoDB 支持事务，MyISAM 不支持
- InnoDB 支持行级锁，MyISAM 只支持表级锁
- InnoDB 支持外键，MyISAM 不支持
- InnoDB 支持 MVCC，MyISAM 不支持

数据同步注意点：
- InnoDB 的事务特性要求同步工具必须正确处理事务边界
- 需要考虑 MVCC 带来的读一致性问题
- binlog 格式的选择（row/statement/mixed）会影响同步的准确性

#### 2. 事务与锁
**Q: 详细解释 MySQL 的 MVCC 实现原理，以及在数据同步时如何保证数据一致性？**

A:
- MVCC 通过 undo log 实现，每行数据都有隐藏字段：
  - DB_TRX_ID：创建/修改该行的事务 ID
  - DB_ROLL_PTR：指向 undo log 的指针
  - DB_ROW_ID：行 ID
- 同步工具需要：
  - 正确获取 binlog position 或 GTID
  - 处理事务完整性
  - 考虑主从延迟问题

#### 3. Binlog 相关
**Q: 详细讲解 binlog 的三种格式，以及各自在数据同步中的优缺点？**

A:
1. ROW 格式：
   - 优点：记录行数据变化，最安全可靠
   - 缺点：日志体积大
   - 适合数据同步场景

2. STATEMENT 格式：
   - 优点：日志量小
   - 缺点：可能导致主从不一致
   - 不建议在同步工具中使用

3. MIXED 格式：
   - 根据 SQL 语句自动选择格式
   - 需要同步工具能够处理两种格式

#### 4. 性能优化
**Q: 在大规模数据同步场景下，如何优化同步性能？详细说明原理。**

A:
1. 并行复制技术：
   - 基于 group commit
   - 基于 schema 分组
   - 基于事务冲突检测

2. 批量同步优化：
   - 合并多个事务
   - 使用 prepared statement
   - 并行应用事务

#### 5. 高可用相关
**Q: 详细描述 MySQL 主从复制的原理，以及可能遇到的问题和解决方案？**

A:
1. 复制原理：
   - 主库写入 binlog
   - 从库 I/O 线程读取 binlog
   - 从库 SQL 线程执行事件

2. 常见问题：
   - 主从延迟
   - 数据不一致
   - 复制中断

3. 解决方案：
   - GTID 保证一致性
   - 并行复制减少延迟
   - 心跳检测机制
   - 自动故障转移

#### 6. 故障处理
**Q: 如何处理数据同步过程中的各种异常情况？**

A:
1. 网络中断：
   - 断点续传
   - 位点保存
   - 自动重试机制

2. 数据不一致：
   - 校验机制
   - 数据修复工具
   - 全量同步能力

3. 性能问题：
   - 监控告警
   - 动态调整参数
   - 限流机制

#### 7. 架构设计
**Q: 设计一个高可用的数据同步系统需要考虑哪些关键点？**

A:
1. 核心组件：
   - 解析器：解析 binlog
   - 传输层：数据传输和转换
   - 应用层：目标端写入
   - 监控系统：状态监控

2. 关键特性：
   - 数据一致性保证
   - 高可用设计
   - 性能优化
   - 可观测性
   - 容错机制
