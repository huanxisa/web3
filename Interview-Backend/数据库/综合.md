# 数据库面试题

## 1. 数据库事务与 MVCC
Q: 请详细解释 MVCC (多版本并发控制) 的实现原理，以及在 MySQL InnoDB 中 MVCC 是如何保证事务隔离性的？

A: 
- MVCC 的核心是维护数据的多个版本，让读写操作互不冲突
- InnoDB 的 MVCC 实现：
  - 使用隐藏字段：DB_TRX_ID（事务ID）和 DB_ROLL_PTR（回滚指针）
  - 通过 undo log 构建版本链
  - 使用 Read View 机制判断数据版本的可见性
  - 通过事务ID的大小对比来判断数据的可见性

## 2. 数据库同步原理
Q: 在数据库同步工具中，如何保证源库和目标库的数据一致性？请详细解释增量同步的实现原理。

A:
- 全量同步：
  - 使用 mysqldump 或 select 语句导出数据
  - 记录同步起点位置（binlog position 或 GTID）
- 增量同步：
  - 通过解析 binlog 获取变更数据
  - 使用 change buffer 优化写入性能
  - 实现检查点机制，记录同步位点
  - 处理主从延迟和网络异常情况

## 3. B+ 树索引
Q: 为什么 InnoDB 选择 B+ 树作为索引结构？与 B 树相比有什么优势？

A:
- B+ 树的特点：
  - 所有数据都存储在叶子节点
  - 叶子节点形成有序链表
  - 非叶子节点只存储索引
- 优势：
  - 更高的查询性能（范围查询优势）
  - 更好的缓存效果
  - 更小的树高度

## 4. 分布式事务
Q: 在数据库同步场景下，如何处理分布式事务？XA 协议和 TCC 模式各有什么优缺点？

A:
- XA 协议：
  - 优点：强一致性，实现简单
  - 缺点：性能较差，资源锁定时间长
- TCC 模式：
  - 优点：性能好，资源锁定时间短
  - 缺点：实现复杂，需要额外补偿逻辑

## 5. binlog 解析
Q: 详细描述 MySQL binlog 的格式类型（ROW/STATEMENT/MIXED）以及如何解析 binlog？

A:
- 格式类型：
  - ROW：记录行变更，数据一致性好，占用空间大
  - STATEMENT：记录 SQL 语句，空间小，可能导致主从不一致
  - MIXED：混合模式，根据 SQL 类型自动选择
- 解析步骤：
  - 读取 binlog header
  - 解析 event 类型
  - 根据不同事件类型解析具体数据
  - 处理 ROW_EVENT 中的 before/after 镜像

## 7. 数据一致性校验
Q: 如何设计一个高效的数据一致性校验机制？

## 8. SQL vs NoSQL 数据库
Q: 请详细对比 SQL 和 NoSQL 数据库的区别，并说明在数据同步场景下各自的优劣势？

A:
- 数据模型差异：
  - SQL：固定的表结构，强schema
  - NoSQL：灵活的数据模型，弱schema或无schema
- 扩展性：
  - SQL：主要垂直扩展，扩展成本高
  - NoSQL：易于水平扩展，原生支持分布式
- 事务支持：
  - SQL：完整的 ACID 支持
  - NoSQL：通常是最终一致性，部分支持事务
- 同步场景考虑：
  - SQL到SQL：schema变更需要严格控制
  - NoSQL到NoSQL：需要处理数据模型的兼容
  - SQL到NoSQL：需要处理数据降维和反范式化
  - NoSQL到SQL：需要处理数据规范化和模型转换

## 9. 主流 NoSQL 数据库对比
Q: 对比 MongoDB、Redis、Elasticsearch 等主流 NoSQL 数据库的特点及应用场景？

A:
- MongoDB：
  - 文档型数据库，类JSON结构
  - 适合半结构化数据存储
  - 支持复杂查询和索引
  - 同步考虑：oplog解析，版本兼容性
- Redis：
  - 内存型键值数据库
  - 丰富的数据类型支持
  - 适合缓存和实时性要求高的场景
  - 同步考虑：RDB/AOF解析，内存占用
- Elasticsearch：
  - 全文搜索引擎
  - 适合日志分析和搜索场景
  - 分布式架构，易于扩展
  - 同步考虑：mapping管理，分片策略
