# Element - 多链 NFT 聚合交易市场 (2022.11 - 2024.04) | 高级区块链后端工程师

## 项目介绍

Element 是一个多链 NFT 聚合交易平台，其核心业务由"聚合市场"与"自有订单簿市场"两部分构成。我于 2022 年底加入团队，主要负责"自有订单簿市场"的架构优化、性能重构与新功能迭代。该自有市场采用"链下签名订单簿 + 链上批量结算"的混合架构模式，作为 Element 聚合生态的重要组成部分，为专业交易者提供低成本、高效率的交易体验。

我参与了多链扩展（Polygon、BNB Chain、Avalanche 等）的架构设计与实现，并持续优化了核心交易系统的性能与稳定性。用户挂单（List）和报价（Offer）时，只需进行 EIP-712 签名，无需支付 Gas 费，订单在链下由 Go 服务进行存储和撮合；当交易匹配后，后端服务将多个订单批量打包，通过单笔交易在链上完成原子化结算。这套架构不仅实现了媲美中心化交易所的毫秒级响应，也极大地降低了用户的交易成本。

## 技术架构

- **Go 应用层 (ElementBackend)**: 基于 Gin 提供 RESTful API，负责订单的接收与多级校验（EIP-712 签名验证、防重放攻击、资产余额预检查）。
- **Go 核心服务层 (ElementBase)**: 包含基于 Redis Sorted Set 的高性能订单簿引擎 (ordermanager)、批量交易上链模块 (chain) 及处理链重组的事件监听服务 (nftchainservice)。
- **数据存储层**: MySQL 负责订单与交易数据的持久化，Redis 缓存订单簿深度、地板价等热数据，支持高并发查询。
- **Solidity 合约层 (ElementContract)**: ElementOrderBook.sol 执行批量原子化结算，ElementVault.sol 安全托管用户待售资产，采用 UUPS 可升级模式支持业务迭代。

## 主要职责

### 1. 主导自有订单簿市场核心系统的优化与重构 (Go)

- **订单簿系统性能优化**：基于 Go 语言，主导重构并优化了高并发链下订单簿系统（对应 ElementBackend），核心模块 ordermanager 完整支持 NFT 的限价单、藏品报价的提交、存储、撮合与管理。通过优化 Redis Sorted Set 和 Hash 的数据结构设计，结合内存缓存策略，确保订单簿深度和地板价的实时更新，核心 API 接口延迟（P99）优化至 50ms 以内。

- **多级订单校验机制设计**：在 Gin 框架的 middleware 中构建并持续优化了多级订单校验逻辑，通过 EIP-712 签名验证、防重放攻击（Nonce 机制）和资产余额预检查，在订单进入撮合引擎前有效拦截了 99% 以上的无效请求，显著降低了系统负载和链上交互成本。

- **订单簿查询性能提升**：设计了基于 Redis 的订单索引与查询机制，支持按价格、时间、用户等多维度快速查询，通过批量操作和管道技术，将订单提交/取消的延迟优化至 100ms 以内。

### 2. 构建高可用的链上结算与事件同步服务 (Go)

- **批量交易上链服务优化**：负责优化链上交互服务，设计了基于时间窗口和队列长度的动态交易批处理（Batching）策略，将多个匹配订单聚合后调用 ElementOrderBook.sol 的 matchOrders 函数完成原子化结算。通过优化批处理算法，单次链上交易可高效聚合 20-50 笔 NFT 转移，使批量成交的单笔 NFT 平均 Gas 成本降低了 40% 以上。

- **链上事件监听与数据同步**：构建并持续优化了高可用的链上事件监听服务（对应 ElementBase/chain/nftchainservice），设计并实现了针对链重组（Reorg）的自动回滚与数据修正机制，确保 Transfer、OrderMatched 等关键事件毫秒级同步至后端数据库，保证了数据最终一致性。通过优化事件处理流程，数据与链上状态的延迟始终保持在 3 秒以内。

- **多链事件同步架构**：设计了统一的多链事件监听框架，支持以太坊、Polygon、BNB Chain 等不同 EVM 链的并发监听，通过连接池管理和重试机制，确保了多链环境下的高可用性。

### 3. 设计并实现可扩展的多链数据索引架构

- **多链适配架构设计**：主导设计了统一的多链数据服务层（对应 ElementBase/chain），通过抽象的 ChainService 接口和可配置的 EVMClient（位于 chainclient/evmclient），实现了对不同 EVM 链（如 Polygon, BSC, Avalanche）的快速适配与扩展。在我加入后，平台从单一以太坊支持扩展至 10+ 条主流 EVM 链。

- **跨链数据索引服务**：开发并优化了 NFT 元数据（Metadata）和所有权（Ownership）的实时索引服务，通过并发处理和批量拉取策略，确保了前端页面和交易系统所需数据的及时性与准确性。支持多链 NFT 的统一查询接口，为聚合市场提供数据支撑。

- **多链资产验证机制**：设计了跨链资产验证流程，确保用户在挂单和报价时，系统能够准确验证其在不同链上的资产余额和权限，支持多链钱包的统一管理。

### 4. 参与核心交易合约的架构优化与 Gas 优化

- **合约架构优化**：深度参与 ElementOrderBook、OrderValidator 等核心合约的优化迭代，明确了链上与链下的职责边界，将复杂的版税查询、报价有效性等逻辑置于链下处理，仅在链上进行最终校验，显著降低了链上 Gas 消耗。

- **订单结构体设计优化**：主导优化了 LibOrder.sol 中的订单结构体设计，确保了数据在 Go 后端与 Solidity 合约之间传输的高效性与一致性。通过优化数据结构，减少了合约调用时的 Gas 消耗。

- **批量结算合约优化**：持续优化 matchOrders 批量结算函数，通过改进算法和数据结构，提升了单次批量交易的容量和效率，在保证安全性的前提下，进一步降低了平均 Gas 成本。
