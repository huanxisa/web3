# Web3 求职面试标准（后端 + 合约方向）

## 总体要求

| 维度 | 说明 |
|------|------|
| **技能可量化** | 能够验证学员是否真的具备完成实际任务的能力。 |
| **项目可展示** | 学员需要有拿得出手的 Demo 或代码库，作为作品展示给面试官。 |

---

## 1. 基础知识标准

学员必须能够清晰回答以下问题（口述 / 笔试均可）。

### 1.1 区块链核心概念

- 区块、交易、Merkle Tree、共识机制（PoW、PoS）、Gas Fee 原理。

**补充要点：**

- BTC UTXO 账户模型的理解。
- 以太坊账户模型：合约账户、EOA 账户。
- 以太坊交易的数据结构及 EIP-1559 / EIP-712 的理解。
- 以太坊账户如何生成，公私钥关系。
- 以太坊区块链浏览器一般会展示哪些信息（能说出大致内容）。
- 以太坊交易 `nonce` 的作用，`nonce` 异常时如何处理。
- 以太坊交易 `input data` 一般放什么数据。
- 以太坊地址长度、有几种地址创建方式。
- 以太坊事件包含哪些内容，浏览器上如何分析事件。
- 以太坊与比特币「快速交易」的方式分别是什么。
- **扩展**：Solana 的共识机制 POH、账户模型以及交易流程是否熟悉。

### 1.2 钱包与签名

- 解释私钥、公钥、助记词。
- 能用代码生成签名与验证签名。

### 1.3 智能合约基础

- 合约生命周期、事件、函数 `modifier`、`storage` vs `memory` 的区别。

**补充要点：**

- `calldata` 的含义及使用场景。
- 数组与 `mapping` 存储区别，在存储槽中是否连续。
- 合约安全如何保障，日常开发有哪些考虑。
- Solidity Gas 优化常见措施。
- 什么是 ABI 编码，如何通过 ABI 编码调用合约方法。
- `call` 与 `delegatecall` 的区别。
- `topic` 的理解，`indexed` 最多可定义多少个。
- ERC-20 与 ERC-721 区别及核心函数。
- `bool` 类型占用字节数；合约中存在大量 `bool` 时如何优化。
- 发行「图文并茂」的 ERC-721（含元数据等）。

### 1.4 常见安全问题

- 重入攻击、整数溢出、权限控制、随机数等问题。

### 1.5 Golang 基础知识

**补充要点：**

- 基本数据类型有哪些。
- `interface` 接口如何实现；作为 value 时的原理。
- 数组与切片（slice）的区别。
- `map` 的底层实现。
- `channel` 的底层实现。
- `select` / `case` 的用法与典型场景。
- `goroutine` 是什么；启动一个 goroutine 大约需要多少内存。
- 并发编程常用包；`sync.WaitGroup` 的作用。
- GMP 调度底层原理。
- 垃圾回收机制原理。
- 内存管理模型。
- GORM 中事务是否需要手动处理。

### 1.6 Uniswap 相关

**补充要点：**

- 对 Uniswap 的整体认识。
- Uniswap V2 与 V3 的区别。
- 增加流动性时 `k` 值是否会变。
- Uniswap 的 Event 有哪些。
- 什么是最优路径及个人理解。
- 闪电贷流程是否清楚。
- 后端需会用 **go-ethereum** 同步链上数据。
- 在 **Sepolia** 测试网发行 ERC-20，并通过脚本在 **Uniswap V3** 创建池子、添加流动性。

### 1.7 项目理解（结合本人项目）

**补充要点：**

- 项目如何支持高并发、高可用。
- 接口响应速度如何优化。
- 扫链过程中出现网络分叉一般如何处理。
- 交易过程中如何保证安全性。
- 项目私钥一般如何存储。
- 项目如何支持多链信息汇聚。
- 链节点是自搭还是使用第三方。

### 1.8 简历扩展（简历有相关内容时）

**补充要点：**

- DeFi 借贷：熟悉的借贷协议（如 Aave），核心业务描述。
- 跨链：公司使用的跨链桥方案（如 LayerZero），架构及 Gas 优化思路。
- Solana、Sui：如何在这些链上交易；高性能链共识原理。
- 多链聚合：聚合业务如何实现，安全性与时效性如何保障。
- 交易所：订单撮合、清算结算、永续合约等业务理解。

**通过标准：** 能用简洁清楚的语言解释上述概念，**80% 以上答对**。

## 2. 编程能力标准

### 2.1 Go 语言后端

- 使用 **Gin** 编写简单 RESTful API，能调用数据库（MySQL / Postgres）与 **Redis**。
- 使用 **ethclient** 读取某合约的事件日志，写入数据库，并对外提供查询接口。

### 2.2 Solidity 合约

- 独立编写并部署 **ERC-20** 合约（支持转账与铸造）。
- 编写简单的 **Staking** 合约（用户存入代币 → 获得奖励）。
- 使用 **Hardhat** 或 **Foundry** 编写单元测试，**覆盖率 > 80%**。

**通过标准：** 完成 Demo 并能清楚解释每个模块的设计。

---

## 3. 项目作品标准

学员至少完成 **1～2 个**可展示的完整小项目，并上传到 GitHub / GitLab。

### 3.1 必选项目（至少 1 个）

- **Meme Token**（含税收 / LP 注入机制）。
- **Staking / Farming 合约 + 后端服务**（存取款、奖励分发，带事件监听）。

### 3.2 可选项目（加分）

- **NFT Market Demo**（上架、购买、转让）。
- **DEX Swap Demo**（简化版 Uniswap V2）。

**通过标准：** 代码完整，README 写清架构与运行方式，能成功运行。

---

## 4. 工具链掌握标准

| 工具 | 要求 |
|------|------|
| **Hardhat / Foundry** | 合约部署、单元测试、代码覆盖率、mainnet fork 测试。 |
| **Go-Ethereum** | 使用 `abigen` 生成 Go 绑定，编写链上交互逻辑。 |
| **Git** | 基本分支管理与 PR 流程。 |
| **Postman** | 调试合约后端 API。 |

**通过标准：** 能在 **1 小时内**完成一次合约部署 + 后端 API 接口调试。

## 5. 面试软技能标准

- 能用英文或中文清晰描述自己做过的项目（合约功能、后端架构、测试方式）。
- 能回答：「若要在生产环境上线该合约 / 后端服务，如何保证安全？」
- 模拟面试中遇到不会的题目，能保持逻辑思考，不直接沉默。

**补充：**

- 项目团队规模、项目周期心里要有大致概念。
- 离职原因需准备合理、专业的表述。

**通过标准：** 表达流畅，能展现思路，具备基本工程师职业沟通能力。

---

## 最终进入面试阶段的标准

需**同时**满足以下条件，方可进入面试阶段：

1. 区块链核心知识答题 **≥ 80%**。
2. 完成至少 **1 个合约项目 + 1 个后端项目**，可运行并有完整 README。
3. 能**独立演示**合约部署 + API 调用全流程，不依赖讲师提示。
4. 能清楚解释自己代码中的关键流程（合约逻辑 / 后端监听 / 数据结构）。
5. 能完成一次 **30 分钟**模拟面试，并达到及格线。

## 附录：Web3 面试模拟题清单

### 初级（基础认知 + 入门编程）

**适用：** 刚完成第 3 阶段（Solidity 基础）或第 4 阶段（后端实战）的学员。

#### 区块链基础

1. 区块链的区块里主要包含哪些数据？
2. 公钥和私钥的关系是什么？
3. 什么是 Gas？为什么会出现 Gas 费高的情况？
4. 请解释 51% 攻击。

#### Go 后端

1. Go 语言里 Goroutine 和线程的区别。
2. 请写一个最简单的 RESTful API：`GET /ping` → 返回 `{ "message": "pong" }`。
3. Gorm 和原生 SQL 的区别是什么？
4. 你会如何在 Go 里处理错误（error）？

#### Solidity 合约

1. `memory`、`storage`、`calldata` 的区别。
2. `view` 和 `pure` 函数的区别。
3. 请写一个最简单的 ERC-20 代币合约（mint + transfer）。
4. 什么是事件（event），它在 DApp 中的作用是什么？

**考察点：** 基本概念是否清晰，能否写出简单的 API 和合约。

---

### 中级（实战能力 + 工程思维）

**适用：** 完成第 5 阶段（合约实战），准备开始真实项目拆解的学员。

#### 区块链基础

1. 什么是 Merkle Tree？它在区块链中起到什么作用？
2. PoW 和 PoS 的主要区别是什么？
3. 请描述一笔交易从发起到上链的过程。
4. 什么是零知识证明？

#### Go 后端

1. 请解释 channel 在 Go 并发编程中的作用，并举例说明。
2. 使用 go-ethereum（ethclient）如何读取某个合约的事件？
3. 如果 API/RPC 不稳定，你会如何保证后端服务的可用性？
4. 请解释 `context.Context` 在 Go 网络编程中的用途。

#### Solidity 合约

1. 如何防止合约的重入攻击？
2. `require` / `assert` / `revert` 的区别是什么？
3. `modifier` 的作用，请举例说明。
4. 你知道哪些合约升级方案？（如 Proxy Pattern）
5. 请列出常见的 Gas 优化方法。

**考察点：** 能否独立写常见合约逻辑，理解 Go 后端链上交互，有初步安全意识。

---

### 高级（综合能力 + 项目经验）

**适用：** 准备第 6 阶段（真实项目）的学员。

#### 区块链基础

1. 区块链为什么具有不可篡改性？请结合哈希和共识解释。
2. 如果一个区块链节点发生分叉，网络会如何达成一致？
3. 解释什么是随机数攻击，为什么链上随机数生成困难？

#### Go 后端

1. 设计一个服务：监听以太坊区块，并把结果写入数据库，你会如何划分模块？
2. 如果后端需要处理上千 TPS 的交易监听，如何优化？（缓存、并发、消息队列）
3. 在 Gin 项目中，如何设计中间件来做身份认证？
4. 请解析 Go 语言内部的并发模型（GMP）。

#### Solidity 合约

1. 设计一个 Staking 合约，支持：用户存入 ERC-20 → 获得奖励 → 取款。
2. 如何在 Hardhat 或 Foundry 里做 mainnet fork 测试？举一个场景。
3. 请解释代理合约（Proxy + Implementation）模式的工作原理。
4. 如果一个合约需要与 Chainlink 预言机交互，你会如何设计？

#### 综合实战题

1. 写一个 Meme Token（带税收机制 + 自动注入 LP）。
2. 写一个 NFT 市场 Demo（用户上架 → 购买 → 下架）。
3. 如果要在生产环境上线你的合约，你会从安全和性能角度做哪些检查？
4. 中心化交易所（CEX）和去中心化交易所（DEX）的区别在哪里，各有什么优缺点？

**考察点：** 能否完成 DApp 全链路（合约 + 后端 + 数据服务），具备工作面试水准。
