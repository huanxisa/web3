# 区块链技术原理 - 区块链密码学基础

数字货币最早也被叫做加密货币（crypto currency），后来越来越多的 ERC20 协议的币被发行之后，慢慢的 currency 换成了 token，但是 crypto 始终被保留。

加密货币，不是说货币信息被加密，相反货币信息以及货币相关的交易活动内容都是公开的，公开的信息包括账户地址、账户持有的各种代币的余额、账户交易代币的转账金额历史等。

比特币和以太坊主要使用到了密码学中的两个功能：哈希、签名。

## 哈希函数

密码学中哈希函数全称为 **Cryptographic Hash Function**。

它有几个个很重要的性质：

1. 抗碰撞性（collision resistance）
2. 隐匿性（hiding）
3. Puzzle friendliness

### 抗碰撞性

哈希函数的抗碰撞性是指在给定一个哈希函数的情况下，难以找到两个不同的输入，它们的哈希值（输出）是相同的。

具体过程：

假设有两个输入，分别用 x 和 y 表示，哈希函数用 H 表示。

其中 **x ≠ y**，如果 **H(x) = H(y)**，两个不同的输出，算出来的哈希值是相等的，就叫做**哈希碰撞**。

理论上哈希碰撞不可避免，因为输入数据的数量远大于输出的空间。比如目前最常见的两个哈希函数 SHA-256 和 SHA-512，它们生成的哈希值分别是 256 位和 512 位。它们所有哈希值的取值的范围分别是 0 ~ 2 ^ 256 和 0 ~ 2 ^ 512。

按照鸽笼理论，那么必定会有两个不同的输入，得到相同输出，也就是一定会发生哈希碰撞。

所以目前哈希函数需要的抗碰撞性，不是不存在哈希碰撞，而是没有高效的方法人为制造哈希碰撞。

即：

给定一个 x，没有便利的方法找到另一个值 y，使得 **H(x) = H(y) 。**

利用哈希函数的抗碰撞性，可以对一个输入 m，计算哈希后得到 H(m)，有人篡改 m 后得到 m'，H(m') 一定不等于 H(m)。那么没有办法篡改内容且不被检测出来，达到**数据防篡改**的效果。

### 隐匿性

哈希函数的隐匿性（或称为“隐私性”）是指通过哈希函数生成的哈希值无法反推出原始输入数据的特性。

这个性质成立的前提是需要输入的可能性无穷大，并且输出的分布足够均匀，保证取值的可能性都差不多。

如果输出空间很大，但是输出结果总是在特定的范围，也很容易被破解。

隐匿性与抗碰撞性两个性质结合在一起，用来实现 digital commitment。

简化过程：

把预测结果作为输入，计算哈希值，然后公布哈希值。

由于哈希函数的隐匿性，不能通过哈希值倒推出输入。

由于抗碰撞性，这个结果值不能被篡改，否则得到的哈希值不对。

区块链中为了保证 x 的取值范围足够大，所以在正常的输入的基础上，有加上了一个随机数 nonce，保证输入足够随机，并且分布足够均匀。

### Puzzle friendliness

所有还在使用 PoW(Proof of Work)共识机制的区块链所需要的一个性质，是代码实现的。

它具有几个特点

1. 仅凭结果难以推测最后的哈希结果；
2. 可以很方便的控制谜题难度，并且谜题一定是有解的；
3. 谜题很难被解决，但是很容易验证。

区块链中应用的具体过程：

1. 经过执行交易后得到当前区块头 Block Header；
2. 区块头有一个早就定好的 difficulty 值，用 2 ^ 256 / difficulty 得到目标值 target；
3. 矿工不断修改 nonce 值，使得 H(Block Header || nonce) <= target；
4. 一旦找到这个 nonce，就把这个 nonce 写到 Block Header 中，并且把 Block Header 发布出去。

以太坊 PoW 时期的代码：

```go
for {

    // 省略部分非重点代码...
    
    digest, result := hashimotoFull(dataset.dataset, hash, nonce)
    if new(big.Int).SetBytes(result).Cmp(target) <= 0 {
        // Correct nonce found, create a new header with it

        header.Nonce = types.EncodeNonce(nonce)
        header.MixDigest = common.BytesToHash(digest)

        // Seal and return a block (if still needed)
        select {
        case found <- block.WithSeal(header):
           logger.Trace("Ethash nonce found and reported", "attempts", nonce-seed, "nonce", nonce)
        case <-abort:
           logger.Trace("Ethash nonce found but discarded", "attempts", nonce-seed, "nonce", nonce)
        }
        break search
    }
    nonce++
}
```

### 以太坊使用的哈希函数

目前大部分使用的哈希函数有两种，分别是 SHA256 和 Keccak256。

其中 Keccak256 更现代，并且安全性更高，它是按照 SHA-3 的标准实现的。

而 SHA256 则是按照 SHA-2 标准实现。

以太坊中与链状态相关，使用的哈希函数都是用 Keccak256，比如 AccountTrie、TransactionTrie、ReceiptTrie，Block Header 中各种哈希、 交易哈希、合约方法签名等。

只有为了保证历史兼容，比如系统合约、discV5 的签名生成、payloadId 等一些不影响链状态的地方还会使用 SHA256。

## ECDSA（椭圆曲线数字签名算法）

区块链由于其去中心化的特点，任何人注册都只需要使用特定区块链的程序提供的方法，在本地就能生成一个公私钥对，就凭借公钥访问各种链或者 Dapp。

公钥起始对应着链上的账户地址，可以随意公开。

而私钥相当于账户的密码，只有持有账户，才可以操作账户执行链上操作。并且通过私钥是可以计算出公钥。

以太坊中使用的非对称加密算法是 ECDSA，它是一种基于椭圆曲线密码学的数字签名算法，广泛应用于比特币和其他区块链系统中。

与 RSA 相比，ECDSA 提供相同级别的安全性，但所需的密钥长度更短，计算效率更高。并且 ECDSA 生成的签名相对较小，便于传输。

详细的数学基础与详细介绍可以查看维基百科的说明：

[https://en.wikipedia.org/wiki/Elliptic_Curve_Digital_Signature_Algorithm](https://en.wikipedia.org/wiki/Elliptic_Curve_Digital_Signature_Algorithm)

### 发起交易

在 go 中，发起任意交易都需要用的私钥：

```go
package main

import (
        "context"
        "crypto/ecdsa"
        "fmt"
        "log"
        "math/big"

        "github.com/ethereum/go-ethereum/common"
        "github.com/ethereum/go-ethereum/core/types"
        "github.com/ethereum/go-ethereum/crypto"
        "github.com/ethereum/go-ethereum/ethclient"
)

func main() {
        client, err := ethclient.Dial("https://rinkeby.infura.io")
        if err != nil {
                log.Fatal(err)
        }

        privateKey, err := crypto.HexToECDSA("fad9c8855b740a0b7ed4c221dbad0f33a83a49cad6b3fe8d5817ac83d38b6a19")
        if err != nil {
                log.Fatal(err)
        }

        publicKey := privateKey.Public()
        publicKeyECDSA, ok := publicKey.(*ecdsa.PublicKey)
        if !ok {
                log.Fatal("cannot assert type: publicKey is not of type *ecdsa.PublicKey")
        }

        fromAddress := crypto.PubkeyToAddress(*publicKeyECDSA)
        nonce, err := client.PendingNonceAt(context.Background(), fromAddress)
        if err != nil {
                log.Fatal(err)
        }

        value := big.NewInt(1000000000000000000) // in wei (1 eth)
        gasLimit := uint64(21000)                // in units
        gasPrice, err := client.SuggestGasPrice(context.Background())
        if err != nil {
                log.Fatal(err)
        }

        toAddress := common.HexToAddress("0x4592d8f8d7b001e72cb26a73e4fa1806a51ac79d")
        var data []byte
        tx := types.NewTransaction(nonce, toAddress, value, gasLimit, gasPrice, data)

        chainID, err := client.NetworkID(context.Background())
        if err != nil {
                log.Fatal(err)
        }

        signedTx, err := types.SignTx(tx, types.NewEIP155Signer(chainID), privateKey)
        if err != nil {
                log.Fatal(err)
        }

        err = client.SendTransaction(context.Background(), signedTx)
        if err != nil {
                log.Fatal(err)
        }

        fmt.Printf("tx sent: %s", signedTx.Hash().Hex())
}
```

### 验证交易

当以太坊收到交易执行验证时，会通过交易中的签名信息复原公钥信息，并使用公钥信息获取的账户的地址，这个过程就相当于在使用公钥验证这个签名：

```go
func TransactionToMessage(tx *types.Transaction, s types.Signer, baseFee *big.Int) (*Message, error) {
    msg := &Message{
       // 省略部分不重要代码...
    }
    // If baseFee provided, set gasPrice to effectiveGasPrice.
    if baseFee != nil {
       msg.GasPrice = cmath.BigMin(msg.GasPrice.Add(msg.GasTipCap, baseFee), msg.GasFeeCap)
    }
    var err error
    msg.From, err = types.Sender(s, tx)
    return msg, err
}

func (s EIP155Signer) Sender(tx *Transaction) (common.Address, error) {
    if tx.Type() != _LegacyTxType _{
       return common.Address{}, ErrTxTypeNotSupported
    }
    if !tx.Protected() {
       return HomesteadSigner{}.Sender(tx)
    }
    if tx.ChainId().Cmp(s.chainId) != 0 {
       return common.Address{}, fmt.Errorf("%w: have %d want %d", ErrInvalidChainId, tx.ChainId(), s.chainId)
    }
    V, R, S := tx.RawSignatureValues()
    V = new(big.Int).Sub(V, s.chainIdMul)
    V.Sub(V, big8)
    return recoverPlain(s.Hash(tx), R, S, V, true)
}

// SignatureValues returns signature values. This signature
// needs to be in the [R || S || V] format where V is 0 or 1.
func (s EIP155Signer) SignatureValues(tx *Transaction, sig []byte) (R, S, V *big.Int, err error) {
    if tx.Type() != _LegacyTxType _{
       return nil, nil, nil, ErrTxTypeNotSupported
    }
    R, S, V = decodeSignature(sig)
    if s.chainId.Sign() != 0 {
       V = big.NewInt(int64(sig[64] + 35))
       V.Add(V, s.chainIdMul)
    }
    return R, S, V, nil
}
```

并且签名中还会包含 chainId 信息，每个不同的链，它们的 chainId 都是不同的，包括测试网的 chainId 同样也是不同的，这就保证了相同的签名，不会再其他的链上生效，防止签名的重放攻击。

### 以太坊 2.0 中各种证明签名

以太坊不再使用 PoW 而是 PoS，验证者所有的操作均需要使用私钥对提议区块、验证区块所的证明、聚合证明、提现等操作都需要使用私钥生成签名，确保验证者参与共识时发送的消息不会被篡改。
